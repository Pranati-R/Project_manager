Product report

Product Manager (Nginx Gateway Manager)

What it does, how it works, how to reach your products and the dashboard, and what each type of project needs.

1What it does

The Product Manager puts all your web products behind one port. Each product gets its own URL path, and you manage the list from a web dashboard. You never edit nginx files by hand.

Without itWith it
server:5173, server:3000, server:8000 – one port per product server:8280/product1/, /product2/, /product3/ – one port, one path each
  • Add, edit, switch off or delete a product in a few clicks.
  • See at a glance whether each product is up (green dot), and test it through the gateway.
  • Roll back any bad change; the last 30 nginx configs are kept.
  • Apache (port 80), your other nginx sites and your apps' processes are never touched.

2How it works

Browser (Tailscale)

Product on 127.0.0.1:port
PartRole
nginx (8280 / 8281)8280 routes each path to its product. 8281 serves the dashboard. Only the Tailscale network and the server itself are allowed in.
Manager (127.0.0.1:8790)The dashboard's backend. Stores the products and generates the nginx config. Runs as a limited user, not root.
Helper (root)The only privileged part. It can do one fixed job: check, install and reload the gateway config.
ProductsKeep running as they do today (Docker, systemd, tmux). They listen on 127.0.0.1 only, so the gateway is the single way in.

Safe apply, every time you save a change:

  1. The manager generates one config from all products.
  2. It is tested alone in a private sandbox (nginx -t), then checked for allowed content and port conflicts.
  3. The live file is backed up and replaced; the whole nginx setup is tested again.
  4. nginx reloads gracefully (no dropped visitors).
If any step fails, the previous config stays live and the dashboard shows the reason. A bad change never goes live.

<server> is the server's Tailscale name or IP (for example box.tail1234.ts.net). Your device must be connected to Tailscale. Ports can be changed in Settings.

On the server, sudo nginx-gateway-ctl status shows the state and prints the addresses.

4How to access registered products

  1. Open the dashboard and sign in, then go to Projects. Every registered product is a row.
  2. The row shows its route, for example /product1 → 127.0.0.1:5173. Click Open to launch it in a new tab.
  3. Or type the address directly: http://<server>:8280/<path>/ (keep the trailing slash).
Row controlUse

A product that cannot run under a path (for example product3) is reached on its own port: http://<server>:8282/.

5How to access the dashboard and add a project

Sign in: open http://<server>:8281/ with a@g.com / 123456. Change the password straight away in Settings → Account (a yellow banner stays until you do).

DocsStep-by-step guides for every project type

Add a project:

  1. Start the product on 127.0.0.1 and note its port.
  2. Projects → Add project. Enter the name, the URL path (for example /product1), the App type and the port. Tick Separate API server if there is one (API port and path such as /api).
  3. Check the live preview of the nginx routes, then press Add and apply.
  4. Press Test on the new row. It checks the app directly, then through the gateway, including its page files.
Command line alternative: nginx-gateway-ctl projects import FILE loads projects from JSON; projects export backs them up.

6Handling different types of project

Under the gateway a product lives at /product1/, not /. So the frontend must be told its base path. The backend never needs a change, because the gateway removes the path before the request reaches it (/product1/api/users arrives as /api/users).

Docker frontendPrebuilt appPass the base path as a build argument and rebuild the image
Backend only (FastAPI, Flask, Express, Django…)Strip prefixNothing. Just listen on 127.0.0.1
Frontend + separate APIAny + Separate API serverBase path on the frontend; point its API variable to /product1/api (e.g. VITE_API_BASE)
App you cannot changeDedicated portNothing. It gets its own port (8282+) at /

Small code fixes, only if the app has them:

  • Router with real URLs: <BrowserRouter basename={import.meta.env.BASE_URL}>. A HashRouter needs nothing.
  • Hard-coded /api/... or /logo.png in code: prefix with import.meta.env.BASE_URL or use the API variable.
  • A backend that writes pages or redirects (redirect("/login")) needs the path too. JSON-only backends do not.
Check before changing anything: nginx-gateway-ctl vite-check ~/my-project/frontend --prefix /product1/ reads the files only and lists what needs fixing.

7Operations at a glance

sudo nginx-gateway-ctl status | restart | logs [-f]    # health and logs
sudo nginx-gateway-ctl update-code [--check]           # pull latest code from GitHub, restart, re-apply
sudo nginx-gateway-ctl rollback                        # back to the previous version
sudo nginx-gateway-ctl verify-isolation                # prove Apache and other sites are untouched
Full guides: dashboard → Docs tab, or the docs/ folder. Print to PDF from the browser for a 3-page copy.
